# OKAMI-101 independent acceptance and test design

Read-only proposal. Source of acceptance: surf101/shared/surf/.cruft/spec101.md. No production edits or completion claim. Blocking Surf and legacy curl remain compatible; HTTP2integration102/curlreplacement133/QUIC are separate. Surf stays independent of Saba.

## Observable contract to agree before implementation

Accepted asynchronous requests have exactly one deferred terminal completion; rejected admission has none and preserves source ownership. Stable handle includes owner/epoch/generation; cancel is a request, never permission to release accepted input before completion. Success moves an independently destructible Response; failure owns no response. Copy request metadata into finite admitted storage, or specify immutable borrowing until completion explicitly; never retain a transient request arena accidentally. A moved owned upload remains held through its final physical write callback. A response/body can outlive request slot reuse and Client shutdown if its scope/allocator owners remain retained. No library callback under a pool mutex; reentrant release uses detached snapshots and no subsequent owner access.

Total request deadline starts before pool admission/queueing and DNS. The exact retained monotonic cutoff is carried through numeric connect, TLS authentication, request/response/body and every redirect. setup_timeout is an additional shorter phase cap. Cancellation reports write effect honestly (NotSent/MayHaveBeenSent/ResponseReceived); no ambiguous write or failed POST is transparently replayed. Fresh retry after a stale idle socket is allowed only when zero application bytes were accepted and the explicit method/replay policy permits it. Even an idempotent retry consumes the original total deadline and finite attempt count.

Pool key is origin scheme/normalized hostname/effective port plus immutable TLS trust/authentication/ALPN and proxy policy identity. Equal DNS endpoint is not equal origin. Different RootPool pointer values alone do not establish complete policy identity; snapshots or immutable profile IDs must have lifetime/rotation rules. Reject unsupported proxy settings explicitly; do not silently ignore them. Redirect reevaluates target policy/key, authority and TLS server_name, strips cross-origin credentials under documented compatibility rules, counts/drains redirect bodies under limits, and never extends the deadline.

Separate configured capacities: origins; connections global/per origin (connecting+active+idle all counted); admitted requests; finite per-origin waiters; request metadata; retained response/upload backing; DNS query/ID workspace; idle TTL/max age. Zero semantics explicit. Capacity reservation changes storage only. Stats report real states and full backing charges, not RSS or requested payload length. One HTTP1 exchange per connection initially; no pipelining claim. Pool eligibility requires a completely parsed body boundary, no EOF framing, no Connection:close, correct HTTP1.0 persistence policy, no upgrade, no unconsumed/surplus bytes, no pending I/O/callback/parser owner. Idle shutdown probes cannot consume bytes from a future response. Failed/cancelled ambiguous streams close.

Task-owned DNS_Connect + async/connection executor + TLS Async_Conn are the real network path. Every TLS session keeps its own pinned task/executor; a general caller cannot call it on another task/thread. Pool coordination uses finite owner notifications/queues and existing workers; neither blocking execute nor curl easy_perform is placed on those workers. Trust/configuration file loading and DNS entropy preparation happen before connection callbacks. Synchronous crypto remains non-preemptible; post-work monotonic deadline checks prevent late success, and cancellation latency documents this limit.

## Smallest first prerequisite: request budget handoff

Existing Executor init lifetime budget remains immutable. Add a distinct finite exchange request budget cap, rotate only while accepted operations/jobs and Surf TLS ownership are proven quiescent. Persistent transport may have no shorter init lifetime cap; the new request cap always bounds its operations. The cap may shorten accepted work but never extend pending operation cutoffs. Clear only after exchange completion/close drain. Public tests must not write private deadlines or invoke an external executor.

Paired test matrix for the validator-owned adapter prerequisite:
1. Init lifetime cap and request cap select minimum; zero lifetime remains valid; malformed/foreign epoch rejected without mutation.
2. Pending read+write retain original cutoffs across attempted rotation; no extension, no duplicate callback, no buffer reuse before terminal callbacks. Rejected rotation preserves both operations.
3. Idle rotation A→B after A completes permits B after A's cutoff, still on the same real TCP/TLS session; B expires at B's own original cutoff. Clock-backward controls do not lengthen monotonic cutoff.
4. Cancellation/close during rotation or timeout drain: exactly once deferred callbacks, no stale cap applied to replacement operation/generation, teardown physical callback can free owner.
5. Deadline elapsed during non-preemptible handshake work prevents authenticated success publication. Keep existing outbound_gate's intentional-rebase negative control detecting the bad implementation.
6. ScopeClosed/allocator grant failures preserve typed causes where available, all physical owners/FDs gone, existing adapter tests unchanged.

Suggested single task owns at most five actual adapter files: connection/connection.odin (cap state/API), connection/operation.odin (submission cap), one focused connection test, one owned loopback host, one runner. Exact filenames follow existing adapter layout; no global table or extra worker. Parent selects final partition with validator.

## Parallel pure HTTP1 pooling prerequisite

http/v1/request_encode currently hardcodes Connection:close. Add an explicit persistent profile preserving existing function/default bytes. response_header_decode acceptsHTTP1.0/1.1 but Response_Head drops the version; add an additive metadata reader/type for precise reuse decision rather than mutate old public aggregates or infer persistence from ContentLength alone. Parser must retain token semantics for Connection close/keepalive. No response fields borrowed from scratch survive without owned copying.

Task A ≤5files: request_profile.odin, request_profile_test.odin, codec.odin only if shared sizing/validation requires it; request profile docs optional. Test literal independent HTTP1wire, ContentLength, method/body rules, aliases, shortdest preflight preservation, exact unchanged legacy encoder wire. Task B ≤5files: new response_persistence.odin, response_persistence_test.odin, codec.odin only if truly necessary, with serialized shared-file handoff. Test version1.0defaultclose vs explicitkeepalive, version1.1defaultpersist vs close token mixedcase/repeats, EOF/upgrade/ambiguous framing exclusions. These are foundations, not async pool completion.

## Full101 owned public loopback acceptance matrix

Use literal independent Python/Go TCP+TLS peers and an owned fake DNS peer. Keep raw accepted connection IDs, request order, exact request bytes, completion count/order, socket/FD counts, actual runtime worker count, source/copy/compiler hashes and physical scope/heap baselines. Clients must use only the public async Surf API; never private pool injection or blocking execute. ASan+TSan validate correctness, native repetitions optional and explicitly not performance certification.

- Compatibility/ownership: blocking original consumers still build/run; async HTTP and HTTPS GET/HEAD/POST success; header/body copies survive caller arena destruction according to selected submission contract; response/header/chunk survives request handle reuse, Client close and late physical release; every rejection preserves complete owner provenance and payload bytes. Reentrant completion destroys response/client header safely. At least one actual nonnil custom source release callback and allocator-failure-at-every-constructor/admission boundary.
- Nonblocking proof: workers1, one peer stalls DNS, another TLS handshake, another header/body/write; independent cheap origins complete before stalled peers release. Observe task Pending/Yield and same fixed worker count. No thread-per-request/offload/blocking wrapper. Queue depth and low work quantum must produce forward progress without busy spin or global head-of-line blocking.
- Reuse/key isolation: two sequential same-origin requests yield one TCP accept; B begins after A deadline but completes under B cap; normalized host/defaultport same key; different hostname same endpoint, scheme, explicit port, trust profile, ALPN and supported proxy identity never share. Rejected incompatible TLS trust never obtains data from existing authenticated connection. Idle TTL/maxage closes then reconnects; deterministic peer close/reset between requests exercises safe zero-byte retry or explicit failure, never duplicate POST body.
- Exhaustion/fairness: global/perorigin connections full, all request/waiter/origin/byte caps at0/exact/max; fail or finite queue according to explicit API, source untouched on reject. Connecting sockets count. Stalled A cannot block ready B; cancellation/expiry of queued head frees only its slot, FIFO/fairness policy testable. Request timeout includes queue wait. Reserved storage growth does not raise budgets; closed scope rejects and all partial allocations roll back.
- Cancellation: before admission, queued, DNS, pending connect, TLS, partial request write, response head, partial body, redirect boundary and completion race. One terminal callback per accepted request; no buffer release before accepted I/O callback; writes report observed effect; cancel stale/foreign token cannot touch replacement request. Cancelling one request does not terminate unrelated pool sessions.
- Deadline: expiry at each phase above with one original cutoff, setup cap shorter/longer than total, redirect chain whose per-hop latency fits but sum exceeds total, wake delayed past deadline, clock movement, cancelled request never turns late success. Record actual phase/branch observed rather than call an elapsed preflight test a parked timeout proof.
- HTTP framing/reuse safety: fragmented/coalesced headers, bounded100/103 beforefinal, CL exact/zero/underflow/overflow, HEAD/204/304, chunked completion/trailers, EOF framed close, Connectionclose/malformed/version1.0, upgrade rejection/explicit transfer, surplus bytes/unsolicited input fail closed. A connection cannot be checked out before complete response boundary or while body owner still imposes retained flow policy.
- Redirects: existing 301/302/303/307/308 method rules and body replayability documented; finite loop, crossorigin credential stripping, HTTPS→HTTP policy, hostname verification mismatch, response body limits on intermediate hops, redirect source ownership, original deadline preserved. Accepted ambiguous upload writes never replayed without explicit permitted semantics.
- Shutdown/stale/concurrency: concurrent producers using declared thread-safe admission API (or explicit owner mailbox) and handles from multiple tasks; perTLS executor affinity persists. Graceful Client close rejects new submits, drains accepted completions; abort cancels/drains; no destroy with live callback storage. Late cancel/stale generations owner epochs/slotreuse cannot affect new session. Runtime shutdown tasks and Client shutdown cooperate, all FDs/scopes/allocations return to baselines after late owners release.

Suggested eventual test ownership seams, each task≤5files: pool state tests+literal fixture host+runner; HTTP/TLS/DNS integration host+peer+runner; cancellation/deadline host+peer+runner; ownership/fault tests+host+runner; existing facade-consumer tests. Keep production pool/kernel, network task driver and request/result ownership tasks separate with agreed public seams. Preserve full101 acceptance even when each prerequisite commits independently; adapters102 and133 remain open.
